# Study 1–16 工程审查与验证记录

本次记录日期：2026 年 11 月 2 日。范围是本地 `nestjs-study-1` 至 `nestjs-study-16` 的源码、依赖配置、测试和教学文档；目标是让各章能独立运行、真实触发教学机制，并能按中文指南学习。

## 审查方法与版本

先确认 16 个目录全部存在，读取每章适用的 AGENTS.md、package/TypeScript/Nest/Vitest 配置、全部业务源码及测试，再执行修改前基线。没有根据编号直接推断知识点；例如 Study 12 实际演示 ModuleRef，而不是循环依赖。

验证环境为 Node.js 24.5.0、pnpm 12.3.4。16 章实际安装的 Nest common/core/platform-express 为 12.3.2、TypeScript 6.0.3、Vite 8.3.5、Vitest 4.1.12。检查时同时核对依赖声明、独立锁文件和已安装 package 的版本及 engines。

保留全部独立项目、主要依赖版本、strict、NodeNext、装饰器元数据和声明输出；未添加数据库或真实 AI 服务。没有为了消除错误增加 any、ts-ignore 或关闭检查。启动端口、日志和临时 Redis 均在本地独立使用，验证后进程已停止。

## 独立进程验证

逐章使用 `node dist/main.js`、分配空闲本地端口，确认实际监听和本章接口响应，不仅依赖 TestingModule：

- 1–8：用户列表、商品列表、quota 429、非法布尔400、公开 Agent、响应转换、个人 Agent 公开查询、AI Mock 生成。
- 9：启动独立、禁用持久化的本地 Redis，通过真实 HTTP 创建任务并读回 `pending`，然后发送 SIGTERM 关闭应用与 Redis。没有使用现有 Redis 数据。
- 10–14：动态模块生成、真实 main 注册的 durable 同标签复用、ModuleRef 模型选择、研究模块懒加载、Mock 身份保护的目录访问。
- 15：创建任务后立即发送 SIGTERM，进程约5.01秒后退出；日志中任务完成先于数据库资源释放，与 app.close 自动回归的顺序一致。
- 16：通过发现的 calculator 工具执行 `10 20` 并返回结果。

16/16 实际启动检查通过。另按 README 顺序实跑了 15 章的 111 条静态 curl 命令（使用独立端口，检查每条成功或失败状态码），全部符合说明；Study 15 的动态任务 ID 与关闭流程由上述真实进程及 e2e 验证。测试不代表真实云模型、支付平台或生产安全能力得到验证。

## 明确保留的教学边界

- 内存 CRUD/任务记录、简单价格计算、模拟数据库、同步模拟支付继续保留；没有事务、重启恢复、多进程共享或容量管理。
- Study 5、7、14 的固定 Token 不具备密码校验、签名、过期和撤销机制。7 演示当前用户资源归属；5、14 的业务是共享目录。
- Study 6 缓存没有 TTL/失效协议；快照在本进程保留，写入后不自动刷新是当前实验设计。
- Study 9 自动测试使用替身；真实 Redis 冒烟验证另列，不把两类证据混为一谈。
- Study 10 的 timeout/maxRetries 不执行重试；Study 11 的租户标签只用于公开 DI 分组；Study 12 手动创建的是操作上下文，不是 Express REQUEST 绑定。
- Study 16 搜索、天气是 Mock，calculator 只做两个有限数字的加法，不执行任意表达式。

后续接入数据库、认证、真实模型等应作为新的独立章节推进。没有将尚未实现的功能登记为课程完成项。
